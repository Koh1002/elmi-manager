# エルみえる管理アプリ（elmi-manager）システム要件定義書

## 1. プロジェクト概要

### 1.1 背景
「エルみえる」は、サミット・トモズなどの小売データを対話型UIで分析できるシステムである。
AWS上にデプロイされ、以下のコンポーネントが連動して動作する：

- **Amazon Cognito** : ユーザー認証
- **AWS Lambda** : APIバックエンド処理
- **Amazon Bedrock** : 自然言語→SQL変換、分析示唆生成
- **Amazon Redshift** : データウェアハウス（SQLクエリ実行）
- **Amazon CloudFront** : フロントエンド配信

現在の課題：
1. テスト・品質管理が手動（ユースケース投入→タイムアウト確認→ロジック検証を人力で実施）
2. ユーザー管理がCognitoコンソールでしか行えない
3. 利用状況やエラーの可視化手段がない
4. AI生成出力（SQL・分析示唆）の継続的な改善ループが体系化されていない

### 1.2 目的
MLflowのような「記録→原因解析→修正提案」のループをシステマティックに回せる管理用WEBアプリを構築する。

### 1.3 対象システム
- URL: `https://dze1oua0wfjfh.cloudfront.net/front.html`
- 認証: Amazon Cognito

### F1: ユーザー管理

**概要**: Cognitoのユーザープールを管理画面から操作できるようにする。

| 機能 | 説明 |
|------|------|
| ユーザー一覧表示 | Cognitoユーザープール内の全ユーザーをテーブル表示（ユーザー名、メール、ステータス、作成日、最終ログイン日） |
| ユーザー新規発行 | メールアドレス・仮パスワードを指定して新規ユーザーを作成 |
| ユーザー無効化/有効化 | 既存ユーザーのアカウントを有効/無効に切り替え |
| パスワードリセット | ユーザーのパスワードを管理者側からリセット |

**AWS連携**:
- `cognito-idp:ListUsers`
- `cognito-idp:AdminCreateUser`
- `cognito-idp:AdminDisableUser` / `AdminEnableUser`
- `cognito-idp:AdminResetUserPassword`

---

### F2: 利用状況ダッシュボード

**概要**: エルみえるの利用ログを収集・可視化する。

#### 記録するログ項目

| 項目 | 説明 |
|------|------|
| timestamp | リクエスト日時 |
| user_id | ユーザーID（Cognitoサブ） |
| user_email | ユーザーメールアドレス |
| natural_language_query | ユーザーが入力した自然言語リクエスト |
| generated_sql | Bedrockが生成したSQL |
| sql_execution_result | Redshiftからの実行結果（サマリ） |
| response_text | ユーザーに返された分析示唆テキスト |
| status | success / error / timeout |
| error_message | エラー時のメッセージ |
| latency_ms | レスポンスタイム（ミリ秒） |
| lambda_request_id | Lambda実行ID（トレーサビリティ用） |

#### ダッシュボード表示内容

- **サマリーカード**: 総リクエスト数、成功率、平均レスポンスタイム、アクティブユーザー数
- **時系列チャート**: 日別リクエスト数推移（成功/エラー/タイムアウト別）
- **ユーザー別利用状況テーブル**: ユーザー名、リクエスト数、成功率、最終利用日
- **リクエスト詳細ログ**: フィルタ・検索可能な全リクエストログテーブル

**データソース**:
- CloudWatch Logs（Lambda実行ログ）
- DynamoDB or S3（構造化ログの永続化先）

---

### F3: テストケース管理・自動実行

**概要**: エルみえるに対するテストケースを管理し、自動実行できるようにする。
MLflowの「Experiment → Run → Metrics」に相当する構造を持つ。

#### テストケースの定義

```json
{
  "test_id": "TC-001",
  "name": "サミット月次売上集計",
  "category": "SQL生成",
  "input_query": "サミットの2024年12月の売上を教えて",
  "expected_behavior": {
    "should_not_timeout": true,
    "max_latency_ms": 30000,
    "sql_should_contain": ["SUM", "sales", "202412"],
    "result_should_not_be_empty": true
  },
  "tags": ["summit", "monthly", "sales"]
}
```

#### 機能詳細

| 機能 | 説明 |
|------|------|
| テストケース登録 | 自然言語クエリ + 期待動作を定義して登録 |
| テスト一括実行 | 登録済みテストケースを一括でエルみえるに投入し、結果を記録 |
| 実行結果記録 | テスト実行ごとに「実行(Run)」として記録（生成SQL、実行結果、レイテンシ、判定結果） |
| 実行履歴比較 | 同一テストの過去Runと比較し、回帰(regression)を検出 |
| 判定（Pass/Fail） | 期待動作に基づく自動判定 + 手動判定の上書き |

---

### F4: エラーログ収集・分析

**概要**: エラーが発生したリクエストを自動収集し、原因分析を支援する。

| 機能 | 説明 |
|------|------|
| エラーログ一覧 | status=error または timeout のログを一覧表示 |
| エラー分類 | エラータイプ別の集計（SQL構文エラー、タイムアウト、Redshift接続エラー、Bedrock応答エラー等） |
| 原因分析ビュー | エラーリクエストの詳細（入力→生成SQL→エラー内容）を1画面で確認 |
| AI改善提案 | Bedrockを使い、エラーパターンに対する改善提案を自動生成 |

---

### F5: 日次改善提案メール

**概要**: 1日1回、エラーログを集約し改善提案をメールで送信する。

| 項目 | 内容 |
|------|------|
| 送信タイミング | 毎日 09:00 JST |
| 宛先 | 固定1アドレス（設定画面で変更可能） |
| メール内容 | 前日のエラーサマリー、エラー件数、代表的なエラーケース（最大5件）、各ケースに対するAI改善提案 |

**メール本文の構成例**:

```
件名: [elmi-manager] 日次改善レポート - 2026-02-25

■ サマリー
  - 総リクエスト数: 142
  - エラー件数: 8 (5.6%)
  - タイムアウト: 3件
  - SQL構文エラー: 4件
  - その他: 1件

■ 改善提案

  [1] タイムアウト - 「トモズの過去3年間の月次売上推移を出して」
      原因推定: 集計期間が長く、Redshiftのフルスキャンが発生
      提案: WHERE句に日付フィルタのヒントをプロンプトに追加
      該当プロンプト: prompts/sql_generation.json L42

  [2] SQL構文エラー - 「サミットのカテゴリ別粗利を教えて」
      原因推定: 「粗利」のカラムマッピングがJSON定義に不足
      提案: column_mapping.json に粗利→gross_profit のマッピングを追加
      該当ファイル: config/column_mapping.json
  ...
```

**AWS連携**:
- Amazon SES（メール送信）
- Amazon EventBridge（日次スケジュール）

---

### F6: プロンプト・設定ファイル管理

**概要**: エルみえるの動作を制御するJSONファイルやプロンプトテンプレートをバージョン管理付きで管理する。

| 機能 | 説明 |
|------|------|
| ファイル一覧 | 管理対象の設定ファイル・プロンプトファイルを一覧表示 |
| 編集・差分表示 | ブラウザ上でファイルを編集し、変更差分を確認 |
| バージョン履歴 | 変更履歴を保持し、任意のバージョンにロールバック可能 |
| テストとの紐付け | 設定変更後にテストケースを再実行し、改善/悪化を確認 |

## 3. 非機能要件

### 3.1 アーキテクチャ

```
[ブラウザ]
    │
    ▼
[elmi-manager フロントエンド]  ← React (Vite)
    │
    ▼
[elmi-manager API]             ← Node.js (Express) or Python (FastAPI)
    │
    ├──→ [Amazon Cognito]       ユーザー管理API
    ├──→ [CloudWatch Logs]      ログ取得
    ├──→ [DynamoDB]             テストケース・実行結果保存
    ├──→ [Amazon Bedrock]       改善提案AI生成
    ├──→ [Amazon SES]           メール送信
    └──→ [エルみえる API]       テスト実行時のリクエスト投入
```

### 3.2 認証・認可
- elmi-manager自体のログインにもCognitoを利用（管理者用ユーザープール、またはグループで分離）
- 管理者ロールのみアクセス可能

### 3.3 デプロイ
- フロントエンド: S3 + CloudFront
- バックエンド: Lambda + API Gateway（or ECS Fargate）
- インフラ定義: AWS CDK or Terraform

### 3.4 データ保持
- ログデータ: 90日間保持（S3にアーカイブ後は1年間）
- テスト実行履歴: 無期限
- 設定ファイルバージョン: 無期限
